# 設備維護知識庫（maint-km-rag）

用過去的維護履歷回答「這台設備出現這個異常，以前怎麼處理」。
混合檢索找出相似紀錄，LLM 重排後只用達標的紀錄歸納答案，每個步驟標註引用列號，可以回到原始紀錄核對。

線上展示：https://maint-km-rag.vercel.app （有範例問題可直接點；「評測結果」分頁有完整數據）

> 原型來自實際工作：工廠維護履歷知識庫，我負責驗收測試（以真實問題逐題評估 Precision）與改善建議。
> 這個公開版用虛構資料、以自己的實作重新建立，不含任何公司資料或程式碼。

## 查詢流程

```
問句 ─┬─ BM25（中文二字詞，症狀欄加權）前 30 ─┐
      └─ 向量（gemini-embedding-2）前 30 ─────┴─ RRF 加權融合 1:2 → 前 20
                                                   │
                         LLM 重排（0～10 分）→ 門檻 0.6 ─┬─ 無達標 → 回覆查無
                                                         └─ 達標 → 範圍篩選 → 綜合研判（標註列號）
```

- **檢索不做廠別過濾**：每次查全庫。問句提到廠別或設備時，在達標之後才篩選「顯示哪些」。
  同廠沒有該設備的紀錄，就列出他廠同型設備的經驗並明說「三廠查無……請確認適用性」，不會把「別廠有經驗」誤報成「查無資料」。
- **門檻決定走不走知識庫**：重排分數都低於 0.6 時直接回覆查無，離題問題不會硬湊答案。
- **歸納而非照列**：作法相同的多筆紀錄合併成一步並列出所有列號；每一步可展開原始紀錄。
- **引用核對**：模型引用的列號必須在顯示的案例中，否則由程式移除並在頁面標示。

## 評測

`data/eval.json`：48 題，標準答案是同一故障型態的所有紀錄。一半沿用履歷用詞，一半刻意換句話說、避開關鍵字。

| 做法 | P@5 | R@10 | MRR | P@5 直接問法 | P@5 換句話說 |
|---|---|---|---|---|---|
| BM25 | 42% | 53% | 53% | 74% | 10% |
| 向量 | 70% | 86% | 82% | 77% | 62% |
| 混合 RRF 1:1 | 55% | 74% | 70% | 81% | 30% |
| 混合 RRF 1:2 | 58% | 78% | 72% | 82% | 34% |
| **混合 1:2＋重排** | **85%** | **95%** | **92%** | **91%** | **79%** |

- 換句話說的問題 BM25 幾乎找不到，等權重融合會被拖累，反而不如只用向量。
- 調成 BM25:向量 = 1:2 後，送進重排的前 20 筆候選涵蓋率最高（向量單獨 93.5%、1:1 為 90.9%、1:2 為 95.5%）；
  只用向量時有一題前 20 筆完全沒命中，加入 BM25 後補回。
- LLM 重排是品質提升最大的一步。門檻 0.6 下，達標紀錄 Precision 83%、Recall 91%。
- 三題「三廠沒有的設備」都正確列出他廠經驗並顯示說明；三題離題問題都回覆查無。

數據來自 `npm run eval`，結果存於 `data/eval_results.json`，網頁的「評測結果」分頁直接讀這份檔案。

## 資料

全部虛構，由兩支腳本產生並進版控：

1. `data-src/make_patterns.py`：請 Gemini 為 12 種設備各設計 6 種故障型態（症狀寫法、原因、處理、問句），存成 `patterns.json`。
2. `data-src/make_records.py`：以固定亂數種子組出 282 筆履歷（一廠、二廠、三廠；三廠沒有輸送帶、天車、鍋爐），並產生評測題與標準答案。
3. `npm run embed`：預先計算履歷向量存成 `data/embeddings.json`，部署時隨程式打包，不需要向量資料庫。

## 說明簡報

8 頁 Marp 簡報：`/slides/index.html`（PDF：`/slides/deck.pdf`）。原始檔 `slides-src/deck.md`，操作畫面為正式環境截圖（`public/slides/img/`）；重建：`bash slides-src/build.sh`。

## 本機執行

```bash
npm install
cp .env.example .env.local   # 填入 GEMINI_API_KEY
npm run dev                   # http://localhost:3000
npm test                      # BM25、RRF、範圍篩選的單元測試
npm run eval                  # 重跑評測（約 5 分鐘）
```

```
lib/bm25.ts                 中文 BM25

```
